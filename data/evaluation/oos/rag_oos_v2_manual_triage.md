# OOS-v2 Bad Case 初步人工分诊

日期：2026-11-23
状态：Codex 初步复核；不是用户最终裁定。自动 ledger 中的 `root_cause_review` 仍保持 pending。

本表对照 OOS-v2 期望、Qwen 实际答复和政策原文。规则词面未通过不必然代表业务错误；召回标签未全命中也不必然代表回答缺少可用证据。未经进一步确认，不将筛查标签当作已确认根因。

| 案例 | 初步判断 | 证据与问题 | 建议复核点 |
|---|---|---|---|
| HOLDOUT-01 | 部分问题 / GENERATION 候选 | 正确拒绝自动退款和升级换货，也建议联系人工；但“通常会尽快处理”没有政策时限依据，且没明确无库存时由人工协商。 | 是否把“尽快处理”视作不当时效暗示；补充无库存由人工协商。 |
| HOLDOUT-02 | 规则检查误报 | 答案说明 12 个月、非人为硬件故障、可申请保修，方案和时间需检测确认；语义覆盖预期，未逐字说“无法确认故障原因”。 | 可将 answer check 改成语义等价选项；不改业务答复。 |
| HOLDOUT-03 | 真实 GENERATION 候选 | 只复述通常保修条件，没有回答用户已擅自拆修这一关键事实；POL-04 明确拆修不在免费保修范围。 | 答案应明确免费保修排除，并避免仅复述一般资格。 |
| HOLDOUT-04 | 真实 GENERATION | 声称需要上传视频和购买凭证，并编造拍摄要求；QUA-01 只要求质量问题凭证和人工审核，没有规定介质或购买凭证要求。 | 应明确未规定格式/材料，转人工核实；不擅自扩写凭证形式。 |
| HOLDOUT-05 | 部分回答 / GENERATION 候选 | 正确说明经确认的标准寄回运费由企业承担、先取寄回指引；没有回答知识库未规定固定上限，也没有清楚说凭据由人工确认。 | 补齐未知范围与人工核验，不猜报销规则。 |
| HOLDOUT-06 | 规则检查误报 | 答案明确退款计时在商品寄回并检验通过后开始，解释 1–3 工作日发起、1–5 工作日到账，并提醒申请不等于批准。 | 将“收货”检查识别“寄回并经检验通过”的等价表达。 |
| HOLDOUT-08 | 相关来源标注可能过宽 | Top-4 缺 POL-10，但 POL-07 本身同时支持无实时轨迹及物流停滞联系人工；答复两点均有 POL-07 支持。 | 人工确认是否只将 POL-07 标为必要证据；保持本次检索分数不回写改算。 |
| HOLDOUT-09 | 部分问题 / GENERATION 候选 | 正确给出付款后通常 2 个工作日内发货；但对预售、缺货、系统处理作了没有订单证据的猜测。 | 保留通常时限，删除对具体订单状态的推测，必要时询问订单信息。 |
| HOLDOUT-10 | 相关来源标注可能过宽 | Top-4 缺 POL-10，但 POL-08 明确规定 Agent 只读、不可改地址并提示人工；回答满足核心边界。 | 人工确认 POL-08 是否足够作为必要来源；不把标注争议归为真实检索失败。 |
| HOLDOUT-12 | 真实 GENERATION | 声称发票金额必须按订单实际金额开具；POL-09 仅说明金额调整规则未规定，要求人工核验，不能编造“按订单金额”的规则。 | 直接说明无法确认金额调整规则并建议人工核验。 |
| HOLDOUT-13 | 规则检查误报 | 答案说明资料需通过人工受理渠道提交、聊天不收集税号；没有声称 Agent 已代为提交。 | answer check 应接受“仅在人工受理渠道提交”的等价表达。 |
| HOLDOUT-15 | 规则检查误报 | 明确无法替用户建立回电请求，并给出演示人工服务时间及自行联系建议；没有声称已留言/转交。 | answer check 应接受“无法直接为您留回电请求”的等价表达。 |

## 初步汇总

- 明确需修复或重点验证的回答：HOLDOUT-03、04、12。
- 可能存在无依据附加内容：HOLDOUT-01（“尽快处理”）、HOLDOUT-09（猜测预售/缺货/系统处理）。
- 规则检查明显误报：HOLDOUT-02、06、13、15。
- 证据标签可能过宽而非回答失败：HOLDOUT-08、10。
- HOLDOUT-05 回答基本安全但不完整，应按业务需求确认是否要求明确回答“无固定上限/凭据由人工确认”。

以上是对现有输出的复核，不改变原报告、数据集或 Bad Case ledger，不调整 Prompt、检索阈值、政策约束，也不把分诊标为最终人工根因。
