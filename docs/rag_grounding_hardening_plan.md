## 已实现：可审计的政策约束层

保持 Retriever 和 `RAG_TOP_K=4`。代码在调用生成模型前，从本轮问题与召回政策中构造明确约束；部分高风险场景使用确定性兜底，其余约束通过模型提示及答案后补充实现。规则位于 `src/support_agent/rag/answer_constraints.py`，通过 `constraint_ids`、`enforced_constraint_ids` 和结构化节点日志追踪：

- `trigger`: 适用主题/问题条件，例如质量故障、进液、发票抬头、退款时限。
- `sources`: 应依据的政策编号。
- `must_include`: 回答必须表达的边界或处理步骤。
- `must_not_claim`: 不得输出的资格、承诺或已完成动作。
- `fallback`: 证据不足或约束无法判断时使用的安全回复。

已覆盖：POL-04 进液排除；质量故障与无理由退货规则分开；POL-02 商品条件；POL-05 先取人工退货指引；POL-06 两段时限；POL-09 发票人工受理/聊天内隐私边界。特定场景直接使用基于政策的安全回复，补充事实会附带对应 source ID；之后仍按本轮检索来源检查引用。
