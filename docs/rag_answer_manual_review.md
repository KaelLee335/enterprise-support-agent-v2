# RAG 答案逐例复核

更新日期：2026-11-15

## 范围和方法

逐条对照 `data/evaluation/v1_eval_cases.json` 的 14 个带答案要点政策问答、`data/policies/` 的政策原文，以及 `data/evaluation/v2_rag_answers.json` 中 Top-4/Top-8 的 28 个生成答案。这里只记录人工定性结果，不把同模型 LLM judge 的汇总分数当作金标准，也不合并成一个准确率。

日期题按签收日为第 0 天核对：11 月 8 日为第 7 天，11 月 9 日为第 8 天，11 月 16 日为第 15 天。来源编号格式检查通过率 100% 只说明引用 ID 在检索来源内，不保证引用内容支持全部结论。

| 案例 | Top-4 | Top-8 | 复核结论 |
|---|---|---|---|

| KB-01 | 允许申请并提示人工核验，但省略商品/配件/包装/再次销售条件 | 同类省略 | 部分覆盖；应补充 POL-02 适用条件 |

## 基线生成对照结论（约束层前）

- Top-8 的召回指标更高，但答案质量没有因此稳定提升：它改进了 KB-06 的时限完整度，却在 KB-04 反转明确排除条款，并在 D4-NA-01 添加了未经证据支持的等待条件。维持 `RAG_TOP_K=4`。
- 基线 Top-4 有遗漏：KB-01 商品状态条件、KB-05 人工退货指引、KB-06 两段时限、发票隐私边界、MVP-KB-BOUNDARY 质量规则分流；约束层 v1 的覆盖结果见下节。
- 对通用 Prompt 增加多条长指令后，`data/evaluation/v2_rag_answers_prompt_v2_top4.json` 出现同一回答前后矛盾；这版已撤回。两条简短规则的定向请求曾停滞并中断，未生成完整报告。再增加“排除优先/答案建议一致”后，KB-04 的样例没有再把进液描述成免费保修，但仍建议检测确认维修；MVP-KB-BOUNDARY 仍只按无理由退货作答，未解决质量问题分流。定向原始输出在 `data/evaluation/v2_rag_answers_prompt_v5_targeted_top4.json`。这仍不足以证明 Prompt 方案有效，`answer.py` 已恢复用户验收的原提示。
- Prompt-only 方案未能稳定解决问题，因此用户选择实现下方的可审计约束层。Docker 当前版本仍只包含先前验收版本；任何源代码改动都需另行同步并在 WSL 重建验收。

## 约束层 v1 评估结果

用户选择实现约束层后，新增 `src/support_agent/rag/answer_constraints.py`，将高风险规则按 ID 匹配、提示或确定性兜底；命中与实际补充的 ID 写入评估 JSON 和节点日志。14 条案例的 Top-4/Top-8 共 28 条输出保存在 `data/evaluation/v2_rag_answers_constraints_v3.json`：引用 ID 校验 28/28；约束匹配 Top-4/Top-8 各 11 条，实际补充/兜底各 6/7 条。完整答案未使用同模型 judge，因此没有报告语义准确率。

关键修复点复核：KB-04 Top-4/Top-8 都使用 POL-04 的进液排除兜底；MVP-KB-BOUNDARY 两档都不再仅按无理由期限判断；发票时效/资格与重开问题使用 POL-09 兜底并明确聊天内不收集抬头/税号；KB-06 两阶段时限完整。普通问答仍由 Qwen 生成，约束后补事实。此后用户已将约束层部署到 WSL Docker，扩充版阶段 6 验收健康检查与 11 个业务用例全 PASS，EXIT=0。该运行验收覆盖选定断言，不代表全部 14 题都通过独立语义准确率评估。
