# V1 → V2 数据迁移记录

## 来源与保留方式

V1 Git 仓库位于本机 `D:\python_project\enterprise-support-agent`。V2 从仓库内的 `data/orders.json`、`data/knowledge/`、`data/eval_cases.json` 和 `docs/architecture.md` 取只读副本；V1 原目录不作为 V2 的运行时依赖。

旧订单没有租户字段，导入时统一放入 `legacy-demo`，不推断真实客户归属。V2 新增的固定演示订单 `1001` 单独属于 `demo-a`。订单查询始终要求 `tenant_id` 条件；目前 `X-Tenant-ID` 是演示范围选择，不是身份认证。

## 规则映射与差异

## 数据解释约束

- V1 旧订单缺失的 `product_type`、`is_customized`、`feedback_date` 和 `issue_description` 保持空值或默认值，不从商品名猜测。
- V1 的“订单号可查”不代表用户身份验证；V2 演示数据库的租户过滤不能描述成生产级认证。
- V1 评估运行记录是历史观测数据，不保证同一结果可在新模型、检索器或 LangGraph 路由下重现。对照时保存版本、运行配置、实际轨迹和失败原因。
- V2 固定案例正确答复：不适用 7 日无理由退货；仍可在签收后 15 日内提交质量售后申请；需要凭证并由人工审核；不承诺退款或审核通过。
